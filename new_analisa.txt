================================================================================
AETHER — CONSULTANT VISION / MULTIMODAL IMAGE SUPPORT
(Provider content-parts + Consultant image attach)
Mode: ADDITIVE. Tidak ada arsitektur stabil yang di-rewrite.
================================================================================

--------------------------------------------------------------------------------
RINGKASAN
--------------------------------------------------------------------------------
Tujuan: mengaktifkan kemampuan vision untuk AETHER Consultant dengan risiko
minimal:
  (1) menambah dukungan pesan multimodal (image content-parts) pada layer provider
      yang SUDAH ADA, dan
  (2) memungkinkan user melampirkan/mengirim image di chat AETHER Consultant,
      sehingga image diteruskan ke LLM dan Consultant dapat "melihat"-nya.

Hasil: SELESAI. Image dikirim sebagai content-parts format OpenAI-compatible
(image_url dengan data URL base64) untuk provider OpenAI-compatible (OpenRouter,
DeepSeek, OpenAI, dsb.), dan sebagai field `images` untuk Ollama. Pesan text-only
berperilaku persis seperti sebelumnya (backward compatible). Modul vision existing
(ImagePreprocessor) dipakai apa adanya untuk memproses/resize/kompresi gambar.

--------------------------------------------------------------------------------
1. OBSERVATION (kondisi awal, terverifikasi dari source)
--------------------------------------------------------------------------------
- src/agent_ai/vision/ LENGKAP dan provider-agnostic:
    * input.py       : ImageInputLoader (deteksi MIME magic-bytes; boundary path).
    * preprocessing.py: ImagePreprocessor.process() -> ProcessedImage +
                        _build_payload() => {"type":"image","mime_type":...,
                        "encoding":"base64","data":...} (payload internal AETHER).
    * policy.py      : VisionPolicy + VISION_REQUIRED_CAPABILITIES (VISION+MULTIMODAL).
    * models.py      : ImageInput/ProcessedImage/VisionRequest/VisionConfig.
  Satu-satunya konsumen sebelumnya: scripts/check_vision.py.
- src/agent_ai/providers/base.py: Message = {role, content:str} -> TEXT-ONLY.
- src/agent_ai/providers/openai_compatible.py: _build_payload mengirim messages
  text-only; literal 'image_url' = 0 hasil di repo.
- src/agent_ai/core/types.py: ChatMessage.content = Optional[str] (text-only).
- src/agent_ai/consultant/service.py: consult(message, provider, root, session_id,
  max_steps, mode) -> memanggil orchestrator.run_continuous_loop(task_text).
- web/django_app/api/{services.py,views.py}: consultant_consult menerima JSON
  (message/session_id/provider_instance_id/model_id/project_id/mode).

2. PROVIDER LAYER — Message content-parts (fondasi, ADDITIVE)
--------------------------------------------------------------------------------
File: src/agent_ai/providers/base.py
- Message menambah field opsional: parts: Optional[List[Dict[str, Any]]] = None.
  Format internal AETHER provider-agnostic:
    {"type":"image","mime_type":...,"encoding":"base64","data":...}
  to_dict() menyertakan `parts` HANYA bila ada (text-only tidak berubah).

File: src/agent_ai/providers/openai_compatible.py
- _build_payload kini melewatkan setiap pesan melalui _to_openai_message().
- _to_openai_message(): pesan tanpa parts -> diteruskan APA ADANYA (content tetap
  string; perilaku request text-only identik dengan sebelumnya).
  Pesan dengan parts image -> content diubah menjadi content blocks:
    [{"type":"text","text":<content>},
     {"type":"image_url","image_url":{"url":"data:<mime>;base64,<data>"}}]
- _to_openai_content_part(): konversi satu part internal -> content part OpenAI.
  Part {"type":"audio"} dsb. diabaikan; bagian teks tetap dipertahankan.
- Streaming: provider ini TIDAK memakai jalur streaming (semua request via
  requests.post non-stream). Tidak perlu fallback streaming khusus image.

File: src/agent_ai/providers/ollama.py (degradasi aman, additive)
- _to_ollama_message(): part image internal -> field `images` (list base64)
  sesuai format multimodal Ollama; content list (bentuk OpenAI) -> teks gabungan.
  Pesan text-only diteruskan apa adanya.

Keputusan: format OpenAI-compatible `image_url` dipakai karena semua provider
cloud AETHER (OpenRouter/DeepSeek/OpenAI) dulunya memakai skema OpenAI; Ollama
diberi adapter terpisah agar tetap benar bila dipakai untuk vision.
