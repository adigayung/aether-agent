3. BAGAIMANA "Open with Editor" TERHUBUNG DENGAN EXPLORER
---------------------------------------------------------------------------
- FileExplorer.vue sudah punya item context menu "Open with Editor" yang
  meng-emit("open-file-editor", { path, name }) dengan path relatif dari
  Explorer (childPath(currentPath, entry.name)) -- TIDAK ada mekanisme
  path/workspace baru.
- Sebelumnya emit itu tidak punya listener (dead action). Sekarang:
      <FileExplorer ... @open-file="openFileInEditor"
                        @open-file-editor="openFileInEditor" />
  Klik kiri file (seleksi + open) dan tombol Edit di panel CHANGES juga
  memakai handler yang sama, sehingga placeholder dummy lama
  ("File: <path>" di status) benar-benar digantikan editor nyata.
- Alur lengkap:
      Explorer -> klik kanan file -> "Open with Editor"
      -> emit open-file-editor -> App.openFileInEditor()
      -> editorFile={path,name}, editorOpen=true
      -> <CodeEditor :key="path"> mount
      -> GET /api/files/content?path=... (ReadFileTool AETHER)
      -> Monaco menampilkan isi file dengan language sesuai extension.
- Boundary: path tetap divalidasi di dalam active project root oleh
  ReadFileTool/WriteFileTool AETHER yang sama dengan Explorer
  (path traversal -> 400, tanpa active project -> 404).

4. BAGAIMANA SAVE / DISCARD / CANCEL BEKERJA
---------------------------------------------------------------------------
- Dirty state: model Monaco memakai "versi tersimpan"
  (model.getAlternativeVersionId()). Buka file TIDAK membuat dirty; undo
  kembali ke kondisi tersimpan juga mengembalikan status "Saved".
- Save (header atau Ctrl/Cmd+S):
      editor.getValue() -> POST /api/files/content {path, content}
      -> WriteFileTool AETHER (atomic write, boundary sama)
      -> sukses: baseline versi diperbarui, dirty=false ("Saved"), emit saved
      -> gagal: file TIDAK dianggap tersimpan, isi editor dipertahankan,
         error tampil di footer editor + diteruskan ke banner error AETHER
         yang sudah ada (tidak ada notification system baru).
- Close (tombol X, klik backdrop, atau Escape):
      tidak dirty  -> modal langsung tertutup (Monaco di-dispose)
      dirty        -> modal konfirmasi "Unsaved Changes" AETHER:
                        [Save]    -> simpan; berhasil = tutup, gagal = editor
                                     tetap terbuka (tidak dianggap tersimpan)
                        [Discard] -> buang perubahan, tutup
                        [Cancel]  -> tetap di editor (perubahan dipertahankan)
      Escape saat konfirmasi terbuka = Cancel.
- Tidak ada jalur close yang menutup editor tanpa konfirmasi saat dirty
  (X, backdrop, Escape, Ctrl+S semuanya lewat requestClose()).

6. MASALAH YANG MASIH DITEMUKAN
---------------------------------------------------------------------------
a. Batas body request gateway AETHER_GATEWAY_MAX_BODY_BYTES = 1.000.000 byte
   (settings existing, TIDAK diubah). File yang dibaca sudah dibatasi 1 MB
   oleh ReadFileTool; jika user memperbesar file mendekati 1 MB, POST save
   bisa ditolak 400 oleh batas body. Perilakunya benar (editor tetap terbuka
   + error jelas), tetapi batas ini perlu dinaikkan bila editor ingin
   mendukung file besar. Tidak dilakukan di task ini agar tidak menyentuh
   konfigurasi gateway global.
b. `.vue` dipetakan ke grammar `html` dan `.toml` ke `ini` karena Monaco
   basic-languages tidak menyediakan grammar khusus Vue/TOML (mapping tetap
   sederhana dan mudah diperluas di editorLanguages.js).
c. Auto-complete/validasi kaya hanya tersedia untuk json/css/scss/less/html/
   js/ts (language service bawaan Monaco). Bahasa lain hanya syntax
   highlighting + fitur editor standar (sesuai scope: tanpa LSP).
d. Server Django yang sedang berjalan harus menyajikan dist/ hasil build
   terbaru (sudah di-rebuild). Bila UI lama masih tampil, hard refresh browser
   (index.html sudah no-cache, tapi sesi lama bisa menahan bundle lama).
e. Fitur di luar scope tidak dikerjakan: tabs multi-file, split, Git diff,
   formatter/linter, autosave, editor persistence, LSP.
