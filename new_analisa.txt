2. RINGKASAN PERUBAHAN
--------------------------------------------------------------------
Konsep: `mode` dikirim per-request ("quick" | "investigate"), default
"quick". Mode menentukan TOOL YANG BENAR-BENAR TERSEDIA bagi LLM (melalui
registry) + instruksi prompt. Pembatasan BUKAN hanya prompt: karena
arsitektur Native Tool Calling hanya menawarkan tool dari registry
(orchestrator._tool_definitions -> ToolRegistry.specs()), tool yang tidak
didaftarkan tidak pernah sampai ke LLM.

a) models.py
   - Konstanta MODE_QUICK="quick", MODE_INVESTIGATE="investigate",
     DEFAULT_CONSULTANT_MODE="quick", VALID_CONSULTANT_MODES.
   - normalize_consultant_mode(mode): nilai kosong/tak dikenal -> "quick".
   - ConsultantResult: field baru `mode` (ikut di to_dict()).

b) tools.py — build_consultant_registry(root, provider, options, mode=...)
   - mode "quick"       : HANYA ConsultantBibleTool (update_project_bible).
                          TIDAK ada list_files/read_file/search_code/
                          run_command. (Bible READ tetap via konteks system
                          message; Bible UPDATE via tool.)
   - mode "investigate" : list_files, read_file, search_code,
                          ConsultantRunCommandTool + update_project_bible
                          (sama seperti sebelum perubahan).
   - Tool tulis/hapus/pindah tetap tidak pernah didaftarkan (semua mode).

c) prompt.py — build_consultant_system_prompt(mode)
   - Prompt disusun: base (identitas/boundary) + blok spesifik mode +
     Task Proposal/bahasa.
   - Quick: "Sumber informasi HANYA Bible + percakapan", melarang
     investigasi source/project, tidak menyebut nama tool investigasi.
   - Investigate: mulai dari Bible, investigasi bertahap HANYA bila perlu.
   - CONSULTANT_SYSTEM_PROMPT tetap diekspor (= prompt investigate, backward
     compatible).

d) service.py — ConsultantService.consult(..., mode=None)
   - normalize mode (default quick), membangun registry + prompt sesuai mode,
     dan mengembalikan ConsultantResult.mode.
   - Session context tetap in-memory & TIDAK direset saat mode berganti.

e) web/django_app/api/services.py + views.py
   - GatewayService.consult(..., mode=None) -> diteruskan ke
     ConsultantService.consult(mode=...).
   - View consultant_consult membaca body["mode"] (opsional) dan
     meneruskannya. Default (tanpa mode) = "quick".

f) web/frontend/src/api.js
   - consult(message, { ..., mode = "quick" }) mengirim field `mode`.

g) web/frontend/src/components/ConsultantChat.vue
   - State `mode = ref("quick")` (DEFAULT QUICK) + daftar MODES.
   - Bar pemilih mode di area chat (di bawah header, di atas messages):
     [ ⚡ Quick ] [ 🔍 Investigate ] + hint + aria-pressed.
   - Setiap pengiriman pesan menyertakan `mode: mode.value`.
   - setMode() hanya mengubah mode; TIDAK mereset sessionId/messages.
   - Placeholder input berubah sesuai mode (indikasi UX).
   - Pesan sambutan menyebut kedua mode.
   - Cleanup: menghapus baris redundan `lastProposal.value = ...`
     (menulis ke computed read-only; no-op + dev warning — sudah tercatat
     sebagai known_bug). Tidak mengubah behavior.

h) styles.css
   - .consultant-modes, .cm-label, .mode-btn (+ .active), .mb-icon,
     .cm-hint: gaya pill, konsisten dengan tema dark AETHER (aksen ungu).

Alur: User pilih mode -> ConsultantChat kirim {message,...,mode} -> API ->
GatewayService.consult(mode) -> ConsultantService.consult(mode) -> registry
+ prompt sesuai mode -> loop existing (AgentOrchestrator.run_continuous_loop,
TIDAK diubah). Task Proposal, Run Task, tool activity, Project Bible update,
provider/model selection tetap sama.

4. LIMITATION / BELUM DIVERIFIKASI
--------------------------------------------------------------------
- Verifikasi mode bersifat struktural + deterministik (registry & prompt)
  memakai FakeProvider. Efek "terasa" Quick vs Investigate pada model cloud
  nyata (kualitas jawaban LLM) tidak diuji e2e dengan API key.
- Belum ada test UI interaktif (klik tombol mode) — validasi frontend lewat
  build produksi + asersi statis pada api.js/ConsultantChat.vue.
- Prompt Quick sengaja tidak menyebut nama tool investigasi; namun karena
  constraint hanya "tidak didaftarkan", bila di masa depan registry Quick
  berubah, prompt perlu disesuaikan agar konsisten.
- Bible READ di Quick tetap lewat konteks system message (bukan tool read
  Bible terpisah, karena memang tidak ada tool tersebut di arsitektur).
- `normalize_consultant_mode` memetakan nilai tak dikenal ke "quick" (fail-
  safe); mode typo tidak menghasilkan error, hanya fallback ke default.
