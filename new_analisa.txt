1. AKAR MASALAH (ROOT CAUSE) — TERVERIFIKASI DARI SOURCE
--------------------------------------------------------------------------------
Gejala (laporan user): Task Proposal card "mengendap" di dasar area chat;
balasan Consultant baru justru muncul DI ATAS card. Card tidak ikut naik.

Hasil investigasi langsung (BUKAN dugaan):

(a) CSS TIDAK menjadi penyebab.
    - styles.css:2681  .consultant-proposal { flex: 0 0 auto; ... }
      => hanya ukuran natural, TIDAK keluar dari flow.
    - Tidak ada `margin-top:auto` sama sekali di styles.css (pencarian = 0 hasil).
    - Tidak ada `position:absolute|fixed`, `order`, atau `align-self` pada
      .consultant-proposal.
    - styles.css:1113  .consultant-messages { flex:1 1 auto; min-height:0;
      overflow-y:auto; display:flex; flex-direction:column; gap:12px }
      => tidak ada `justify-content` (flow normal, bukan space-between/flex-end).
    Kesimpulan: kontrak layout benar; card SECARA CSS berada di dalam flow.

(b) Penyebab SEBENARNYA = STRUKTUR DOM di ConsultantChat.vue.
    Sebelum perbaikan, template dirender sebagai:
        <div class="consultant-messages" ref="scroller">
          <div v-for="(msg, i) in messages" ...>                      <-- pesan
             ... (bubble user/assistant, tools) ...
          </div>
          <div v-if="sending" class="consultant-thinking">…</div>
          <div v-if="lastProposal" class="consultant-proposal"> … </div>   <-- DI LUAR v-for
        </div>
    => Card di-render di LUAR loop `v-for`, sebagai child TERAKHIR container.
       Akibatnya card SELALU di-append setelah SELURUH daftar pesan, terlepas
       dari pesan mana yang menghasilkan proposal. Saat user mengirim pesan
       lanjutan, balasan baru masuk ke dalam `v-for` (sehingga muncul DI ATAS),
       sementara card tetap berada di posisi terakhir container (DI BAWAH).
       Inilah yang membuat card tampak "terpaku di dasar".

CATATAN: card TIDAK pernah benar-benar out-of-flow (tidak absolute/fixed).
Masalahnya adalah POSISI RENDER statis (selalu terakhir), bukan `position` CSS.


--------------------------------------------------------------------------------
2. PERBAIKAN YANG DITERAPKAN (frontend-only, minimal, terarah)
--------------------------------------------------------------------------------
File diubah: web/frontend/src/components/ConsultantChat.vue (satu file).

(1) Memindahkan blok Task Proposal KE DALAM loop `v-for="(msg, i) in messages"`,
    tepat setelah konten pesan (bubble + tools), diterapkan hanya untuk pesan
    assistant yang memiliki proposal:

        <div v-if="msg.role === 'assistant' && msg.taskProposal" class="consultant-proposal">
          <div class="cp-head">
            <span class="cp-title">Task Proposal</span>
            <button class="run-task-btn" type="button" :disabled="running"
                    @click="runTask(msg.taskProposal)"> … </button>
          </div>
          <pre class="cp-body">{{ msg.taskProposal }}</pre>
        </div>

    => Card kini mengalir secara KRONOLOGIS: ia muncul persis setelah pesan
       yang menghasilkannya. Balasan Consultant berikutnya (pesan baru di
       `v-for`) otomatis muncul DI BAWAH card; card "naik ke atas" seperti
       bubble biasa.

(2) Menghapus blok `v-if="lastProposal"` yang dulu dirender di luar loop
    (sumber duplikasi posisi statis).

(3) `runTask(proposal)` kini menerima proposal dari pesan terkait
    (`@click="runTask(msg.taskProposal)"`), dengan fallback ke
    `lastProposal.value` bila argumen tidak ada — sehingga perilaku Run Task
    tetap sama:

        function runTask(proposal) {
          const target = proposal || lastProposal.value;
          if (!target || props.running) return;
          emit("run-task", target);
        }

CATATAN: `.consultant-proposal` TIDAK dipindahkan keluar dari
`.consultant-messages`, tidak dibuat fixed/absolute/order, dan tidak diubah
CSS-nya. Perubahan murni pada urutan render DOM.
