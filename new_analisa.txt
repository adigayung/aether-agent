4. PENGGUNAAN isRunning / isSubmitting / RUNNING TASK
---------------------------------------------------------------------------
- isRunning (baru): `computed(() => Boolean(runningTaskId))` = "ADA task yang
  sedang RUNNING". Dipakai untuk:
      * menampilkan tombol Stop (Agent Input & TaskComposer);
      * indikator status UI (taskTag fallback "running").
  TIDAK dipakai untuk `:disabled` input/Submit. Input Agent selalu bisa submit.

- isSubmitting (existing: `submitting` ref): true selama request createTask
  belum selesai. Dipakai:
      * mencegah double submit (submit() menolak saat disabled=true);
      * label tombol "Sending…" + `:disabled` pada Run Task.
  Setelah respons diterima, `submitting=false` -> Send kembali tersedia
  WALAU Agent masih RUNNING. Stop (untuk task RUNNING) tetap tampil.

- runningTaskId (baru, single source of truth = TaskRecord backend):
      * diisi dari GET /api/tasks/queue (task dengan queue_state === "running");
      * diisi dari event SSE `task_started` (task yang benar-benar mulai);
      * diisi dari respons createTask bila queue_state === "running";
      * TIDAK membuat polling baru: refresh mengikuti penanda `queueRefresh`
        yang sudah ada (submit / event terminal / stop) + sekali saat mount.
  Karena id ini berasal dari queue, Stop selalu menunjuk task RUNNING yang
  sebenarnya — bukan task terakhir yang dikirim, pending, atau proposal
  Consultant.

2. SEMANTIK MODE SIMULASI (`--simulate`)
---------------------------------------------------------------------------
DILARANG & TERBUKTI TIDAK DIJALANKAN:
  - `git clone`, `python -m venv`, `pip install`, `npm install`, `vite build`,
    `manage.py runserver`; membuka browser; menulis/menyalin file (termasuk .env).

  sekali (dibuktikan oleh check [4]).

URUTAN RENCANA + PENANDA STATE per langkah:
  [DETEKSI]   root, marker AETHER, versi Python, git/node/npm
  [CLONE]     SKIP (instalasi sudah ada) | "root belum ada; langkah pertama =
              git clone <REPO_URL> -> <root> (butuh koneksi, tidak dijalankan)"
  [VENV]      SKIP (sudah ada) | AKAN: `<sys.executable> -m venv <root>\venv` (LOKAL)
  [DEPS]      SKIP (stamp cocok) | AKAN: `pip install -r requirements.txt` (koneksi)
  [ENV]       SKIP (.env ada) | AKAN: salin deployment.template -> .env (LOKAL)
  [FRONTEND]  SKIP (dist/index.html ada) | AKAN: `npm install` (koneksi) +
              `node node_modules/vite/bin/vite.js build` (LOKAL)
  [LAUNCH]    AKAN: `<python> manage.py runserver <host>:<port>` (LOKAL, BLOCKING)
              + info/WARNING status port
  RINGKASAN:  "<n> langkah butuh koneksi, <n> langkah LOKAL, <n> langkah SKIP"
              + "Tidak ada perubahan file / unduhan yang dilakukan (dry-run murni)."

Semantik exit code: 0 bila simulasi selesai (langkah "butuh koneksi" hanya
informasi, bukan kegagalan); non-zero hanya bila argumen/root tidak dapat
diproses.  Flag `--check`, `--skip-frontend`, `--rebuild-frontend`, `--host`,
`--port` tetap dihormati di jalur simulasi (tercermin di rencana).
